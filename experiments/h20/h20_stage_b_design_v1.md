## 1. Hypothesis

**H20 Stage B: when the positive value of one odour is LEARNED by the agent's own learning module (a fixed reward training, learning frozen during the test) instead of supplied, the adopted agent Agent14 chooses the source of that odour over a source whose odour was presented equally often without reinforcement, as it does with the supplied value.** In the H21 choice task (World7, two sources 10 apart crosswind, midline start 20 downwind, 2 x 2 balance over odour identity and side, 400 rows x 600 steps, the choice = the dwell majority), (i) the learned arm's P(V) is within 0.05 of the supplied arm's on the same rows [M2(a)], (ii) it exceeds the sham-trained arm's by at least 0.20 [M2(b)], (iii) every 2 x 2 cell is at least 0.70 [M2(c)], and (iv) the filter still carries the gain over the gate agent with the same learned values [M2(d)]. The agent is Agent14 = ph24.Release + ph23.Agent9 with the counter starting at 240 (src/ph28.py:92-97), G 2, gate on, C0; learning ON only in the training phase (3.4), OFF in the test. The learned value must pass a registered check before the task (section 7, ML).

1. **A narrow hypothesis, choosing a rewarded odour over a neutral one in a task that controls access to both, balanced over odour identity and side.** Section 1; the task is the H21 task (C0, equal whiff opportunity from the midline start), 2 x 2 balance (World7's cell permutation, world seed + 10000); the learned codes follow the balance (3.6).

## 3. How the learned value enters the adopted pathway

### 3.1 Where learning lives and what it writes (read)

- Every agent constructs its own learning module and odour codes: ph11.py:115 `self.mb = MB4(runs, parallel=False, gated=True, rng=rng, **MB)` with MB = dict(K=200, C=4, sparsity=0.05, eta_d=0.10, eta_p=0.30, beta=0.15) (ph11.py:53); ph11.py:116 `self.codes = np.stack([self.mb.odour(101), self.mb.odour(102)], 1)`. Channel 0 always carries the code of odour 101, channel 1 that of odour 102.
- **Codes are fixed per row index**, not per seed: ph4.py:29-36 draws each row's code from `np.random.default_rng(seed)` with the odour's id as the seed, 10 active units of 200 (round(0.05 x 200), ph4.py:33). So row i has the same pair of codes in the bench, the development run and the evaluation (spec v4 section 7.0: 'the set of per-row odour codes is fixed across runs'). What varies with the world seed is which channel is valued (World7's balance).
- Weights start equal: ph4.py:26 `self.w = np.full((runs, C, K), float(w0))`, w0 = 1.0 (ph4.py:19-20). The value is ph8.py:63-65 `valence(code) = (out0 - out1) + (out2 - out3)` with `out` the weight average over the code's active units (ph4.py:37-39). With all weights 1.0 every odour's value is exactly 0.0.
- The update, ph8.py:71-99: with a code present, an extinction feedback from the current value (ph8.py:74-91; parallel=False puts it back onto compartments 0 and 1, ph8.py:88-90; gated=True silences it while external reinforcement arrives, ph8.py:78-81); depression `-eta_d x reinf x tc_now` (ph8.py:92, :94) and potentiation `+eta_p x tr_past x code` with `tr_past = tr x (reinf <= 0)` (ph8.py:93, :95); weights clipped to [0, 2] (ph8.py:96; wmin 0, wmax 2 from ph4.py:19-20); code trace `tc` and reinforcement trace `tr` decay by 1 - 1/5 = 0.8 per step (ph8.py:97-99; tau 5 by default, ph4.py:19-20). Reward is compartment 1 (ph15.py:60 and :155: `rv[rows, 1]` for the rewarded source), so a rewarded odour's w1 falls and its value rises.
- **The module draws no random number:** ph4.py:25 stores `rng` and no line of ph4.MB or ph8.MB4 uses it (the only draw, ph4.py:31, uses its own seeded generator for the code). Training therefore does not advance the agent's generator (read; bench (i1) checks the generator state).
- The H15 E2 protocol, as run: ph15.py:141-164. For each phase `for _ in range(TRAIN): a.mb.step(code=code, reinf=rv)` (ph15.py:156, TRAIN 30 at ph15.py:24); reinforcement only for the trained group (ph15.py:155); `for _ in range(gap): a.mb.step()` after the first phase (ph15.py:157-158, GAP 50 at ph15.py:138); the values read out by `valences` (ph15.py:74-76, the same `mb.valence` on each code; ph15.py:159); then `a.mb.tc[:] = 0.0; a.mb.tr[:] = 0.0` (ph15.py:160: the relocation keeps the weights only). No world step and no agent step is taken during training (spec v4: 'No navigation').

### 3.2 What Agent14 reads (read)

  - through `self.chan_valence()` (ph14.py:52-55): **`known` if it is not None** (ph14.py:53), zeros if 'learn' is ablated (ph14.py:54), **otherwise the live read-out of the learning module** `mb.valence(codes[:, k])` (ph14.py:55). Used by the gain (ph23.py:62), the gate (ph23.py:64-66) and the filter (ph23.py:79, :88-89);

The learning module's output reaches the pathway only if something puts it into `known`, or if the adopted act is edited.

### 3.4 The training protocol and why its order matters (read and inferred; measured at bench (t))

**Protocol (registered as H15 E2's, one odour rewarded, one presented without reinforcement; the v3 outline's 'B'):** per row, on the agent's own module:
1. the NEUTRAL odour's code (channel 1 - good) for 30 steps, no reinforcement;
2. 50 silent steps (`mb.step()` with no code and no reinforcement);
3. the VALUED odour's code (channel good) for 30 steps with reinforcement on compartment 1 (trained group) or none (sham group);
4. read-out of both values; `tc` and `tr` cleared (ph15.py:160); learning frozen from here.

**What the rule writes, row by row (read from ph4.py:42-63, ph8.py:71-99; the arithmetic is inferred):**
- Step 1 (neutral first, fresh module): all weights 1.0, so the value of the neutral code is exactly 0, the extinction feedback is 0, `tr` is 0, and **no weight changes**; `tc` on the neutral units is 1.
- Step 2: no code, no reinforcement: no weight change; `tc` on the neutral units decays to 0.8^50 = 1.43e-5.
- Step 3 (trained): on the valued units w1 falls by 0.10 per step (tc_now = 1) and is clipped at 0 from the 10th step; the feedback is gated off (reinforcement present), `tr_past` is 0 on every compartment (compartment 1 carries reinforcement; the others have `tr` 0). So **the valued value is exactly (1.0 - 0.0) + (1.0 - 1.0) = +1.0 in every row.** On the neutral units not shared with the valued code, the surviving code trace gives a small depression of w1: 0.10 x 1.43e-5 x (1 + 0.8 + 0.8^2 + ...) = about 7.1e-6 in total. On the u units the two codes share, w1 is 0. Hence **the neutral value is u/10 + (10 - u)/10 x 7.1e-6: about +7.1e-6 where the codes share no unit, about +0.1000064 where they share one, +0.2 where they share two.** Positive in every row.
- Sham: no reinforcement anywhere, so `tr` stays 0 and every value stays exactly 0: **the sham values are exactly 0.0 / 0.0 in every row**, and the sham arm is Agent14 at 0/0.
- **The opposite order (valued first) is not equivalent.** At the neutral presentation the reinforcement trace is still alive (tr1 = 0.8^50 = 1.43e-5 after the gap), and the potentiation term `+eta_p x tr_past x code` raises w1 on the neutral units by 0.30 x 1.43e-5 = 4.3e-6 on the first step; the neutral value becomes about -4.3e-6, the feedback then pulls it back at about 1.5 percent per step, leaving about -2.8e-6 after 30 steps. **A NEGATIVE neutral value where the codes share no unit** (inferred). This is the rule's timing sign (ph4.py:12-14: code before reinforcement depresses, reinforcement before code potentiates), i.e. backward pairing.
- **Why the sign matters more than the size.** Agent14 treats any v < 0 as a negative odour: it is never gated (ph23.py:66 requires v >= 0), never top (ph23.py:89), not handed to navigation while nothing is held (the H19 (a) condition v >= 0), and while it is held the agent flees (ph23.py:77, :100). A neutral value of -3e-6 would put the agent in the +1/-1 regime, where the release's adoption is ON HOLD (decision:release-negative-scope-on-hold; T4 at H26: P(V) 0.772, lost rows 123). The v3 outline's check 'neutral within +-0.1' would pass it. Hence the fixed order (neutral first) and the sign clause of the check (7, ML).

**Code overlap (inferred from the code sizes; the actual count is a fixed property of the code set, read at bench (t)).** Two independent sets of 10 of 200 units share u units with the hypergeometric probabilities P(u = 0) 0.5915, P(1) 0.3268, P(2) 0.0727, P(>= 3) 0.0091 (computed with awk): about 237, 131, 29 and 4 of 400 rows. The rows with u >= 2 (about 33, sd about 5.5) carry a neutral value of 0.2 or more.

**The check (ML, section 7), and why its neutral bound is +0.15, not the outline's +0.1.** Under this protocol the one-shared-unit residual is 0.1 + 6.4e-6 (inferred), just above +0.1, so a +0.1 bound would split rows by the last digits of a float. The code's own quantum is 0.1 per shared unit; +0.15 passes u <= 1 and fails u >= 2.

### 3.5 What a learned magnitude does in the pathway (read)

With learned values v_V (valued) and v_N (neutral), 0 <= v_N < v_V:
- **Filter, keep, gate, H19 (a) and flee are order-only.** top = present & (v >= 0) & (v == v_max over present) (ph23.py:88-89): with both present it is the valued odour only; with the valued odour absent it is the neutral odour. keep = held & (v_h == v_max or v_h < 0) (ph23.py:91): true when the valued odour is held, or the neutral odour is held with the valued odour not present, false when the neutral odour is held with the valued odour present. The gate zeroes the neutral response while the valued odour is held (0 <= v_N < v_V, ph23.py:66). No flee (no negative value). **Every mask equals its +1/0 value on every (row, step) for any 0 <= v_N < v_V** (read; bench (g) checks it exactly). The v_h == v_max test compares the held odour's value with the maximum of the same array, so v_V = +1.0 learned and +1 supplied give the same truth value; no tolerance enters.
- **The gain is magnitude-dependent.** y' = y x (1 + G x max(v, 0)) (ph23.py:62): the valued channel x (1 + 2 v_V) = x 3 exactly when v_V = 1.0; the neutral channel x (1 + 2 v_N): x 1.0000142 where u = 0, about x 1.2 where u = 1, x 1.4 where u = 2. The gained response feeds the circuit (ph23.py:74) and the evidence release comparison (ph23.py:70). **This is the only place where a learned value differs from the supplied +1/0 in the agent** (read), and it acts on the neutral channel only.
- **What the record says about a neutral gain of 1.2.** A single ungained whiff reaches 0.756 of threshold; a single whiff gained x 1.5 (G 0.5 at v 1) holds (peak 1.996) (record:h20-post-bench-diagnosis-result). Gain 1.2 and 1.4 were never measured: whether a single neutral whiff then holds is not known (a linear reading gives 0.91 and 1.06 of threshold; the circuit is not linear). Bench (g) measures it.
- **Why a neutral gain should matter little for the choice (inferred, not measured).** Under the adopted filter, navigation is value-driven and selection does not steer when values are unequal (the accepted consequence recorded with the H23 adoption, master_plan.md 'The architecture as currently adopted'): nav follows top-valued whiffs whenever the valued odour is present, whatever is held (ph23.py:91-92). A neutral hold formed more easily changes nav only where keep is true for it, i.e. while the valued odour is not present (the presence counter's window, 300 steps after a valued whiff, or the 59-step prior). No bar rests on this reading; bench (h) measures the T1 difference before any task seed is used.
- **The counter and the release read no value** (ph23.py:83-85; ph24.py:54-62): identical by construction; bench (i3) checks the counter and the release fields.

### 3.6 The 2 x 2 balance with learned codes

World7 assigns which channel is valued and on which side it sits (a cell permutation from world seed + 10000). The code on the valued channel is odour 101's in the cells where odour A (channel 0) is valued and odour 102's in the others; the overlap u is symmetric in the two codes, so the neutral residual has the same distribution in every cell in expectation. Which row indices fall in which cell changes with the world seed; the per-cell counts of u are printed (bench (t), run). The sham group gets the same presentations in the same order in every cell.

- **(i3) Counter and release fields** of the learned arm equal the supplied arm's wherever the trajectories are equal (they read no value).

- **(i5) Pathway-off and known-answer with the learned values == with +1/0, bitwise** (G 0, gate and filter off in pathway-off; the held odour fixed in the known-answer arm, ph17.py:56-63; both use the value only through its sign, ph23.py:77 / ph17.py:61, and the H19 (a) line v >= 0, ph17.py:63; all learned values are >= 0 after the check).

- **(i7) Order-only masks:** at the measured learned values, top, keep, gate and the H19 (a) mask equal their +1/0 values on every (row, step) of the learned T1 run (3.5).
- **(i8) Reproduction:** the harness reproduces H26's recorded T1 row for row (Agent14 at +1/0 on 1985/2085: V 371 / N 28 / tie 1, and the 400 row outcomes). A reproduction of a recorded result; those seeds' verdict role is spent and nothing is judged on them.

**What is NOT claimed as an identity.** The learned arm is **not** expected to be bitwise the supplied arm in any row: even where the codes share no unit the neutral value is about +7.1e-6, not 0.0, so the neutral gain differs in the fifth decimal. Whether a row's trajectory (positions, holds, nav) is nevertheless identical is measured (bench (h), the run), not presumed. (Section 12 point 2 gives the protocol variant under which the u = 0 rows would be bitwise.)

### 3.8 Relaxations and world changes: none

- **No new state.** The learning module is adopted (H8 v2 with the extinction gate, per decision:phase7-2-gate; the learning loop from H15 Run 2), and Agent14 already constructs it (ph11.py:115-116). The read-out is the module's own function.
