## 1. Hypothesis

**H20 Stage C: with its learning module ON during the run (the H15 Run 2 learning loop: one update per world step, from the agent's own position, reinforcement delivered at the sources), the adopted agent Agent14 uses the positive value it learns at the rewarding source to keep choosing that source over the punishing source before it has learned anything about the punisher, and it keeps H15 Run 2's avoidance of the learned punisher and Run 2's long-horizon search.** In the H15 Run 2 world (World6, 400 rows, 200 starting in the punishing plume (P-start) and 200 in the rewarding plume (R-start), 5400 steps, learning on from step 0; E1-C), (i) fewer R-start rows visit the punishing source than with H15 Run 2's agent on the same rows, and fewer than with the same Agent14 whose learned positive values are removed from the read-out [M2, the gain]; (ii) search is kept: late unrecovered at most 0.10 and within +0.10 of H15 Run 2's agent in each start group [M3]; (iii) avoidance is kept: the punisher's learned value, the late punishing dwell and the comparison with no learning as in Run 2's Q3 [M4]; (iv) the rewarding source is still reached and dwelt at after avoidance, within Run 2's allowed gaps of H15 Run 2's agent [M5]; and, in the controlled-experience evaluation with learning ON in the test (E2-C), a trained Agent14 dwells less at the punisher and reaches the reward more than a sham-trained one, and reaches the reward within 0.10 of H15 Run 2's agent under the same training [M7]. The agent is Agent14 = ph24.Release + ph23.Agent9 with the counter starting at 240 (src/ph28.py:92-97), G 2, gate on, filter on, release on (at negative holds as section 12 point 3 decides); the value reaches it through a per-step read-out of its own module written into `known` (3.3); no adopted module is edited.

### 1.1 The owner's four conditions for H20 (episode:2026-09-20-h20-design-v1), and where each is met

1. **A narrow hypothesis, choosing a rewarded odour over a neutral one, in a task that controls access to both, balanced over odour identity and side.** The H15 Run 2 world has no neutral source: it has a rewarding and a punishing source. The narrow choice this world contains is the R-start agent's choice, after it has learned the rewarding odour's value and before it has ever been punished, between that source and a source whose odour it has never been reinforced on: at that moment the punisher's odour is, to the agent, an unvalued odour (its learned value is exactly 0, or a small positive residual where the two codes share units; 3.8). M2 measures that choice. Access: both plumes are in the world for all 5400 steps; the balance over which source rewards is Run 2's (the permutation after the world draw, ph15.py:38-41, 200/200); side and odour identity are balanced by World2's draw (ph11.py:61-65) as in Run 2, and the result is reported by which odour is rewarded.
2. **Known-valence, learning and integration checks separated.** Stage A, Run 2 and H21-H26 were the known-valence checks; Stage B was the learning check (closed shown). **Stage C is the integration check only:** the learning module on during behaviour in the world of H15 Run 2, both signs, natural visits, with Run 2's values as the reference. Nothing about Stage C is claimed from A or B.
3. **Controls with the same exposure and no reinforcement, fixed order and initial state, learned values checked; the main measure the choice itself.** The controls: H15 Run 2's own agent on the same rows (reference), Agent14 with the learned positive values removed from its read-out (positive-off; the within-agent control for the gain), Agent14 with no learning (Run 2's no-learning arm), Agent14 with supplied +1/-1 (Run 2's known-valence arm). In E2-C the sham group gets the same presentations and gap without reinforcement (spec v4 section 4). The initial state is Run 2's (the agent constructed fresh; in E2, relocation keeps the weights only, ph15.py:160). Learned values are printed per block and per row (Run 2's measures, ph15.py:116, :233-238) and checked as Q3(a), Q5 and the E2 manipulation check. The main measure M2 is a behavioural event on every assigned R-start row (visited the punishing source at least once), with no-choice not arising (every row either visits or does not).
4. **One behavioural pathway named and justified, negative avoidance's priority stated, empty-selection tests told apart from revision tests.** The pathway is the adopted one (gain, gate, filter with presence, release) with the value read out on every step; nothing is added to the agent except, if the owner chooses it, the release's scope rule at negative holds (3.6). Avoidance's priority is the adopted flee (ph23.py:77, :100: a held odour with a negative value sets the target crosswind whatever navigation would do), and a negative odour is never handed to navigation while nothing is held (ph23.py:89: top requires v >= 0). The rows start from the empty state (nothing held) as in Run 2; revision is not a separate test.

### 1.2 What "the gain" means here (the owner's H20 bullet)

The bullet reads 'C, the gain in the H15 Run 2 world with learning on, with Run 2's avoidance and long-horizon search values as the reference'. This design reads 'the gain' as **what that adopted value pathway adds, with the value learned during the run, to what H15 Run 2's agent did in the same world**, and measures it on the one behaviour where Run 2 recorded a positive value doing nothing:

- **The gain, measured by M2:** in R-start rows, Agent14 learning on against (a) H15 Run 2's agent learning on, and (b) Agent14 learning on with the learned positive values removed from its read-out, on the same rows: the share of rows that visit the punishing source at least once over the 5400 steps.

## 3. How learning reaches the adopted agent while it runs

### 3.1 The learning loop in the H15 world (read)

- ph15.simulate (ph15.py:79-118), per world step: sense (:91), `a.act` (:92), `w.move` and the wall reflex `a.bump` (:93), `at = w.at_source()` (:94, within HIT_R 3.0 of a source, ph11.py:102-103, ph9.py:31), then, if learning is on, ONE module update from the row's own position: `code, rv = inputs(a.codes, w.good, at); a.mb.step(code=code, reinf=rv)` (:95-98). ph15.inputs (:55-61): the code of the source the row stands at, reinforcement 1.0 on compartment 1 at the rewarding source and on compartment 0 at the punishing source (:60). Whiffs away from a source are never presented to the module (spec v4 section 2).
- The rule (ph8.py:71-99; Stage B design 3.1 in full): with a code and reinforcement together the extinction feedback is gated off (ph8.py:78-81), the code's weights on the reinforced compartment fall by eta_d 0.10 per step (tc_now = 1 during a stay, ph8.py:92, :94), clipped at 0 (ph8.py:96). **In this world the code and the reinforcement always arrive together** (ph15.py:58-60: both are `at`), so the extinction feedback never acts in-world, and a value moves only while the row stands at a source.
- Consequences (inferred from the rule, checked at bench (v)): at the rewarding source v_R rises by 0.1 per reinforced step from 0 and saturates at +1.0 after 10; at the punisher v_P falls by 0.1 per step. A natural visit is 6-9 steps (spec v4 section 4), so after the first visit v_R is about +0.6 to +0.9 (measured: receivers' block-1 median +0.95 in P-start, Run 2 eval line 41) and v_P about -0.6 to -0.9 (measured: -0.892 at the end in G3, line 190). Once the row leaves the source nothing changes until the next visit, except a potentiation term of order 0.3 x 0.8^25 (about 1e-3 or less) when one source's code arrives while the other source's reinforcement trace has not decayed (the sources are at least 14 apart, at least 23 steps at speed 0.6).
- ph15.valences (:74-76) reads both values with the module's own `valence`; Run 2 printed them at the end of every block (:116).

### 3.2 What Agent14 reads, and why the adopted act fails with learning on (read)

- Agent14's act is ph23.Agent9.act (ph23.py:60-104) inside ph24.Release.act (ph24.py:54-63). It reads the value in two ways:
  - `self.chan_valence()` (ph14.py:52-55): **`known` if it is not None** (:53), zeros if 'learn' is ablated (:54), otherwise the module's live read-out `mb.valence(codes[:, k])` (:55). Used by the gain (ph23.py:62), the gate (:65-66) and the filter (:79, :88-92);

- **Consequence.** With `known = None` (the setting in which chan_valence would read the module live) the act fails at ph23.py:77 (indexing None). H15 Run 2's Agent3 does not have this problem: its act reads the held odour's value live when `known` is None (ph14.py:74-79). The Stage B design found the same (Stage B design 3.2); Stage B wrote the read-out into `known` once.
- **The H15 harness cannot drive Agent14 unchanged either (read):** ph15.run_e1 turns learning on only if `a.rule == "agent"` (ph15.py:125), and simulate records the selection measures and the per-block values only under the same test (:110, :116). ### 3.4 Arms that intervene on the read-out (read)

- **positive-off:** the mirror writes `minimum(v, 0)`: every learned positive value is replaced by 0, negative values are kept. It removes the learned positive value from the agent's read-out and nothing else (the module, its weights and the negative values are untouched). For Agent3 it is an identity: Agent3 reads values only through their sign classes v < 0 (ph14.py:93) and v >= 0 (ph14.py:83), which min(v, 0) preserves; bench (i4) checks it bitwise, and Run 2's measured identity of the intact and no-learning R-start rows (lines 42, 62) is its behavioural trace.
- **no-learning:** the module is not called and `known` is 0/0 on every step (Run 2's arm, abl 'learn', ph15.py:47). For Agent14 this equals Agent14 at supplied 0/0, which equals Agent10 at 0/0 (Stage B identity (i4), measured bitwise in World7).
- **known-answer:** learning off, `known` supplied +1 at the rewarding and -1 at the punishing odour (Run 2's known arm, ph15.py:46).

### 3.5 The modules with a value that changes during the run (read, with the inferred consequences)

The value pair (v_R, v_P) of a row moves through these regimes: (0, 0) before any visit; (+x, 0) or (+x, +0.1u r) after rewarded steps (u shared code units, 3.8); (0, -y) after punished steps with R never visited; (+x, -y) after both. The masks depend only on the ORDER and SIGN of the pair; the magnitude enters only the gain.

- **Gain (ph23.py:62):** y' = y x (1 + 2 max(v, 0)). Zero effect at v <= 0; x (1 + 0.2 k) after k rewarded steps (x 1.2 after one, x 3.0 from ten). Stage B bench (g2), measured: a single whiff from rest reaches 0.756 of threshold ungained and holds in every row at gain 1.2 and 1.4. So from the first rewarded step on, a single R whiff can form a hold; the magnitude beyond 0.1 hardly changes hold formation. Gains between 1.0 and 1.2 (values in (0, 0.1), which occur for the punisher's shared-unit residual while R is being learned, 3.8) were never measured: bench (g) measures them.
- **Gate (ph23.py:64-66):** while an odour is held, an odour with 0 <= v < v_h is zeroed. At (0, 0): nothing gated (equal values). At (+x, 0) holding R: the unvalued punisher's odour is gated out of the circuit and the evidence release; holding P (value 0): R is higher, not gated. At (+x, -y) or (0, -y): a negative odour is never gated (v >= 0 fails), so a punisher whiff while R is held reaches the circuit and can release the R hold through the evidence release (ph23.py:70) and be selected, whereupon the flee acts: avoidance's priority is kept by the gate's sign clause. A value that crosses 0 changes the gate's mask on the next step only; the test compares values of the same array, so no tolerance enters (Stage B 3.5).
- **Filter (ph23.py:79-92):** top = present & v >= 0 & v == v_max over present (:88-89); keep = held & (v_h == v_max or v_h < 0) (:91); nav = keep ? hit : any(whiffs & top) (:92). At (0, 0) both odours are top: the filter is inert (Agent8 == Agent6 at equal values, ph21.py:43-44 and H23's identities). At (+x, 0): R top; a held punisher odour with value 0 is not kept, so only R whiffs steer; nothing held: only R whiffs steer while R is present. - **Presence counter (ph23.py:82-85, start 240, ph28.py:97):** reads whiffs only, no value.
